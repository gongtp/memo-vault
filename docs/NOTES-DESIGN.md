# 日常笔记功能设计

日期：2026-10-23。状态：历史设计。2026-10-24 已改成普通文档编辑器，移除归档和回收站；旧内容恢复成普通文档。当前行为与验证限制见 README.md 和 SECURITY.md；以下保留原设计与验收目标。

## 1. 定位与原则

在 Memo Vault 内增加独立的「笔记」模块，用来记录生活琐事、想法、工作记录和购物清单。沿用现有浅灰背景、白色卡片和紫色强调色。

核心体验：进入笔记 → 新建 → 直接输入 → 自动保存。用户不必先起标题、选类型、选分类或学习 Markdown。

第一版提供完整的记录、查找、整理、恢复和加密备份闭环，不扩展成知识库或任务管理系统。

## 2. 导航与页面

- 桌面：将现有「安全笔记 · 规划中」改为可点击的「笔记」，与账号管理同级。
- 手机：底部导航为概览、账号、笔记、设置。概览新增「写一条笔记」快捷入口。
- 笔记首页：页标题与新建按钮、搜索框、全部/置顶/归档筛选、标签筛选、笔记列表。回收站放在更多菜单中。
- 桌面使用左侧列表、右侧阅读/编辑区域；手机点击笔记进入全屏阅读，点击编辑进入全屏编辑器。
- 首次空状态：「把今天想记住的事写下来」，提供「写第一条笔记」按钮。搜索无结果显示清除筛选，不与空库混淆。

列表每项展示标题、两行正文摘要、更新时间、最多两个标签；清单额外显示完成数，例如 2/5。置顶项置于前部，其余默认按最近更新排序，可切换按记录日期排序。归档和回收站不计入默认列表。

## 3. 记录与编辑

### 3.1 新建

点击新建直接进入编辑器，光标落在正文。标题为空时采用第一行非空正文作为显示标题，超过 30 字省略；只有清单时取第一项。允许只填写标题，完全空白退出时不产生笔记。

记录日期默认今天，可在更多选项中修改，适合补记昨天的事情。创建时间、更新时间由系统维护，与记录日期分开。

### 3.2 编辑器

编辑器顶部：返回、保存状态、完成。正文上方是可选标题，底部是简短工具栏：清单、标签、撤销、重做。记录日期、置顶、归档、删除放入更多菜单。

正文支持文本段落、换行、项目列表和可勾选清单；可混合使用，不要求先选择笔记类型。第一版不做复杂富文本、表格、嵌套块或 Markdown 双模式。

清单：回车新增下一项，空项再次回车退出清单；勾选后显示划线，保持原位置，避免手指操作时条目跳动。清单是笔记内容，不附带到期时间、优先级和提醒。

阅读态的清单可直接勾选；普通正文点击编辑后修改，减少误触键盘。新建则直接进入编辑态。

### 3.3 保存

- 输入停止约 600 毫秒后保存；持续输入时最多约 3 秒触发一次快照保存，具体间隔结合设备性能调整。
- 点击完成、返回、切换笔记或模块时，先完成待保存写入，再离开编辑器。
- 状态必须区分「待保存」「正在保存…」「已保存到本机」「保存失败，点击重试」。只有数据库事务提交成功才能显示已保存。
- 不因每次保存弹提示、重新渲染编辑器、重置滚动或移动光标；中文输入法组合输入期间不打断输入。
- 保存失败时保留当前前台编辑内容和重试入口，不显示成功；用户主动离开前需要明确选择重试或放弃本次未保存更改。
- 点击完成后回到阅读态；自动保存下不使用有歧义的「取消」按钮。撤销/重做服务于当前编辑过程，不承诺跨刷新恢复编辑历史。

## 4. 查找与整理

采用「标签 + 置顶 + 归档」，不同时引入文件夹、分类和标签。

| 功能 | 规则 |
| --- | --- |
| 搜索 | 搜索标题、正文、清单、标签；忽略英文大小写；仅在解锁后的内存中执行 |
| 标签 | 可不设置，可多选；输入名称直接新建；按名称去重；标签筛选使用单选，减少组合复杂度 |
| 置顶 | 一键置顶或取消，适合常用事项；不另设收藏功能 |
| 归档 | 从日常列表移走，内容仍保留，可恢复；不会自动归档已完成的清单 |
| 日期 | 默认按更新时间排序；可切换按记录日期排序；日期区间筛选作为后续增强 |
| 搜索范围 | 默认搜索当前筛选范围；提供显式「包含归档」开关；回收站独立搜索 |
| 标签管理 | 重命名同步修改关联展示；删除标签只解除关联，明确提示受影响笔记数量 |

单条更多操作提供复制全文、置顶/取消置顶、归档/移出归档、移入回收站。复制必须由用户主动触发。

## 5. 删除与恢复

普通删除移入回收站，提供短暂的「已移入回收站 · 撤销」操作，不要求重复确认。回收站显示删除日期与保留期限，支持恢复和永久删除。

建议保留 30 天，到期后在下一次成功解锁时清理，不承诺后台定时执行。永久删除和清空回收站需要确认。恢复时恢复原归档状态与标签；已删除标签不自动重新创建。

回收站随整库加密备份保存。恢复历史备份仍按原删除时间计算期限；导入预览提示已过期项目将清理。删除本机笔记不会修改此前导出的备份。

## 6. 锁定、备份与兼容

复用现有主密码和加密信息库，不新增笔记密码。不把正文、标题、标签、草稿或搜索词存入明文 localStorage、日志或外部服务。

保留切后台立即遮挡内容并锁定的原则。不能依赖页面关闭或切后台事件完成最后一次异步写入，频繁前台保存才是主要保障。后台锁定时未提交的最后少量输入仍可能丢失；不可宣传「绝不丢字」。需要验证加密快照与锁定的竞态：锁定后不得恢复明文界面、保留明文草稿或让陈旧写入覆盖新会话。

已有「操作前再次验证」设置需扩展说明：关闭时解锁后直接使用笔记；开启时在打开已有笔记、开始编辑或执行复制/删除等主动操作前验证，同一编辑过程的自动保存不重复弹密码框。需定义验证授权随关闭笔记、离开编辑或锁定失效；新建笔记不额外验证。

导出包含账号、笔记、标签、回收站和设置。导入预览分别显示账号数、活动笔记数、归档数、回收站数，明确整库替换，不能让「导入笔记」误解为只影响笔记。两台设备仍需通过导出和导入手动迁移。

旧库升级补齐空笔记集合，不改变已有账号。升级数据格式版本，旧客户端必须明确拒绝不支持的新格式，避免旧代码保存时删除笔记。新客户端继续读取旧备份；导入旧备份时明确提示其不含笔记，确认替换会清空本机笔记。

当前导入文件上限为 8 MB。保存前需按最终加密封包大小检查，避免生成无法重新导入的备份；达到上限时解释原因并保持原库可用。

## 7. 建议数据结构与实现边界

笔记使用独立模型，不复用账号备注字段：

```text
Note
  id
  title                用户填写标题，可空；显示标题由内容推导
  blocks[]             text / bullet / checklist；稳定 block id
  tagIds[]
  recordDate           YYYY-MM-DD，本地日历日期
  isPinned
  archivedAt           时间戳或 null
  deletedAt            时间戳或 null
  createdAt
  updatedAt

NoteTag
  id
  name
```

时间戳统一存储 UTC，界面按用户本地时区展示。recordDate 不做 UTC 换算，避免跨时区导致记录日期漂移。

账号与笔记共用整库写入队列和冲突保护。需要将现有只处理 accounts 的加密、校验、会话、密码修改、设置修改、导入导出路径升级为保留所有模块的统一快照，任何操作都不能覆盖其他模块。

内容以文本安全渲染，不接受任意 HTML。建议第一版限制标题 100 字、单篇正文合计 20,000 字、每篇 10 个标签、单个标签名 20 字；这些限制在输入、保存和导入三处一致校验。实际容量指标需结合当前整库加密方式在手机上测量后确定。

笔记编辑建议拆为独立模块，不继续把所有交互堆入 app.js；不要求为此先完成整个项目的框架迁移。

## 8. 交付范围

第一版完整交付：独立导航、列表与阅读、新建与编辑、简单清单、自动保存与失败处理、全文搜索、标签、置顶、归档、回收站、整库加密备份与旧库迁移、手机适配。

后续根据实际使用增加：图片附件、日期筛选、重复笔记、少量手动模板、版本历史。图片需要先解决容量和备份上限；提醒需要单独设计可靠的通知能力。云同步、分享协作、AI 总结、复杂富文本不属于本轮。

## 9. 核心验收

1. 解锁后从列表点击一次新建即可开始输入，不要求标题和标签。
2. 中文连续输入、清单操作、滚动编辑时，保存不会跳光标或丢内容。
3. 显示已保存后刷新、重新解锁、导出再导入，内容、勾选状态与整理状态一致。
4. 保存失败、容量不足、多个页面冲突时不出现虚假的成功状态，不静默覆盖其他修改。
5. 切后台立即隐藏内容；重新解锁展示最后成功提交的版本；锁定与写入竞态不会回显明文。
6. 账号编辑、修改主密码、设置修改和笔记自动保存交错时，双方数据均保留。
7. 旧库升级不丢账号；旧备份替换对笔记的影响有明确预览；不支持的新版本被拒绝。
8. 删除可恢复；归档可检索；回收站过期清理遵循同一规则且写入成功后生效。
9. 手机软键盘不遮挡正文与完成按钮；主要点击区域至少 44×44 CSS px，输入字号至少 16px，有明确的焦点和按钮名称。

第一版已落实上述核心范围。当前工具栏为文字、清单、列表、撤销和重做，标签及日期直接显示在编辑器上方；正文使用原生文本输入块，避免复杂富文本。手机软键盘、iPhone 主屏幕模式仍需真机验收。
