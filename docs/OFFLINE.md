# 离线使用与 GitHub Pages 部署

## 发布

运行 `npm run check`，再运行 `npm run build`，将生成的整个 `dist/` 部署到 GitHub Pages。Actions 如已配置，应在上传 Pages artifact 前运行构建，并上传 `dist/`。不要直接发布源码目录：源码 `sw.js` 是模板，构建才会写入完整资源清单和摘要。每次修改程序后都要重新构建并发布全部产物。

支持根路径和 `/memo-vault/` 等仓库子路径，manifest、资源与 Worker 均采用相对地址。保留原域名和路径，不要为了离线功能更换地址、删除网站数据或重新建立信息库。本次离线功能不修改账号/笔记存储格式、主密码或模块锁定策略。

## iPhone 首次准备

1. 使用 Safari 联网打开已部署的 HTTPS 地址。
2. 分享 → 添加到主屏幕。
3. 保持联网，从主屏幕图标打开应用，进入「设置与备份 → 离线使用」，等待显示「离线已就绪」。必须在实际日常使用的这个窗口确认，不能只以 Safari 标签页的状态为准。
4. 如已有记录只在 Safari 中，先在 Safari 导出备份，再按原有导入流程导入主屏幕应用；不要清理旧数据。已有主屏幕应用可直接更新并准备，无需移除图标。
5. 开启飞行模式，关闭并重新从主屏幕打开应用，验证解锁、新建/修改笔记、等待「已保存到本机」、重开后内容仍在。

离线仍按原模块设置解锁，账号和笔记继续保存到本机。首次从未访问过的窗口不能凭空离线下载应用。外部网站链接仍需要联网。离线缓存不是同步或备份。

## 状态与更新

- 「正在准备」：程序文件仍在下载，请保持联网。
- 「离线已就绪」：当前控制页面的 Worker 已确认所需程序文件齐全。
- 「离线尚未就绪」或检查失败：展开详情，联网后点击「检查 / 重试离线准备」。无需删除已有数据。
- 「新版本已下载」：先等内容保存，再关闭所有本应用窗口（含相关 Safari 标签页），重新打开。不会强制刷新正在编辑的页面。

安装时逐文件验证 SHA-256 摘要；网络中断、发布文件不一致、空间不足时，不用不完整的新缓存替换旧版。缓存名称隔离应用路径，清理仅涉及该路径的旧程序缓存。系统可能回收网站存储，应用会请求持久存储但不保证获准；仍需定期导出备份。存储策略参考 [WebKit 官方说明](https://webkit.org/blog/14403/updates-to-storage-policy/)，更新等待机制参考 [Service Worker 生命周期](https://web.dev/articles/service-worker-lifecycle)。

## 验证范围

自动测试覆盖子路径离线导航、全部应用依赖、下载失败与配额失败回滚、更新保留旧版、限定缓存清理、缓存缺失检测与修复、不拦截个人备份及任意请求。既有账号/笔记测试一并执行。

桌面浏览器使用独立测试地址，缓存后停止本地服务器，再重新打开、解锁和保存笔记验证。可使用 `node scripts/preview.mjs 42891 /memo-vault/` 复现子路径预览。手机尺寸布局检查不能替代 iPhone 真机验收；发布后仍需在实际 iPhone 主屏幕窗口完成上述飞行模式清单，包括软键盘输入、切后台再解锁及更新后的记录保留。
