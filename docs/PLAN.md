# Memo Vault 技术方案与页面设计

状态：2026-10-22，已完成 v0.3 本地加密实现。首次使用公开初始密码 a12345678，输入一次；新增主密码修改与“操作前再次验证”开关，新库默认关闭重复验证。此开关不影响本地/导出加密。IndexedDB 持久化、后台锁定与加密导入导出已接通。当前使用原生 ES Modules，Vue 工程迁移及 PWA 发布仍待实施。具体实现及安全边界以 [SECURITY.md](SECURITY.md) 为准；以下技术栈和路线包含未来规划。

## 1. 产品定位与一期边界

一个面向个人的、以 iPhone 主屏幕使用为优先的私人信息库。第一期提供账号信息管理，后续按独立模块加入安全笔记、订阅与个人资料。

第一期正式版：创建信息库、主密码解锁、账号增改删、平台/账号/备注搜索、分类、常用收藏、第三方登录方式记录、密码显示与复制、自动锁定、加密备份导入导出、PWA 安装与离线应用外壳。删除进入回收站，30 天后在下一次解锁时清理。

暂不做：多用户、团队共享、自动填充、浏览器扩展、云端数据库、自动同步、附件、验证码种子与恢复码管理。网页不能直接替代 iOS 原生密码自动填充扩展。订阅提醒以后需要额外设计推送或日历方案，不能依赖网页在后台准时执行。

采用“纯程序发布 + 每设备本地存储 + 文件导入导出迁移”。GitHub 仓库和 Pages 发布产物不含任何个人数据或个人备份；正式版初次打开为空库，提供“创建信息库”和“导入已有信息库”两个入口。当前设计原型内置的虚构示例也不进入正式发布版本。

浏览器与手机使用同一套程序，各自持有独立的数据副本。通过导出、传输文件、导入，在另一设备继续使用。如果后续需要自动同步，应另行选择密文同步后端；GitHub Pages 本身只提供静态资源托管，不具备后端存储能力。不要将 GitHub Token 放进页面或将真实账号数据提交到仓库。

## 2. 确定的技术栈

| 层 | 选择 | 理由 |
| --- | --- | --- |
| UI | Vue 3 + TypeScript + Vite | 适合表单和模块化页面，静态构建，维护成本低 |
| 样式 | CSS 变量 + scoped CSS | 控制移动端细节，避免重型桌面组件库 |
| 路由 | Vue Router / Hash history | GitHub Pages 刷新深层路由无需服务器回退 |
| 状态 | Pinia | 管理解锁状态、模块状态；敏感状态不做明文持久化 |
| 存储 | IndexedDB + idb | 异步事务、版本迁移，保存加密数据与非敏感配置 |
| 加密 | Web Crypto API | PBKDF2-SHA-256 派生密钥，AES-256-GCM 认证加密 |
| PWA | vite-plugin-pwa / Workbox | manifest、图标、离线应用外壳、受控更新 |
| 测试 | Vitest + Playwright | 加密/迁移单测，核心流程端到端测试，补充 iPhone 真机验收 |
| 发布 | GitHub + GitHub Actions + GitHub Pages | 自动测试构建后发布静态产物，无需服务器 |

当前交付的 HTML/CSS/JS 已连接真实加密与存储层，不等于已搭好上述 Vue 技术栈。后续迁入 Vue 时复用并重新验证加密协议、存储和锁定生命周期，不能引入明文状态持久化。

## 3. 数据与加密设计

浏览器页面解锁 → 内存中派生密钥 → 解密 vault → 在内存中显示账号 → 修改时加密后写入 IndexedDB。GitHub Pages 只传输程序文件，不接收信息库。

数据量较小时采用整库加密，一期账号名称、登录名、网址、分类、收藏、备注和密码都包含在密文内。未解锁时不读取搜索索引或展示平台名称。密文外只保留格式版本、算法标识、KDF 参数、盐与 IV 等必要元数据；这些参数不含密码。

- 初始化产生至少 16 字节随机盐。PBKDF2-SHA-256 初始基线 600,000 次迭代，正式定版前在目标 iPhone 测量解锁耗时、复核安全参数，并把实际参数写进封包，支持迁移。
- AES-GCM 每次加密生成新的 12 字节随机 IV，使用 128 位认证标签。头部格式、版本和派生参数的规范化编码作为 AAD，修改参数导致认证失败。
- 解密密钥不可导出，只驻留内存，不写入 localStorage / IndexedDB / 日志。主密码不保存；无服务端找回。忘记密码且无可解锁备份时无法恢复数据。
- 解密失败不覆盖原数据。保存操作串行化，IndexedDB 事务提交完成再显示保存成功。多个标签同时写入采用锁与修订号冲突检查，避免最后一次写入静默覆盖。
- 新信息库使用公开初始密码进入，之后可在设置中修改，新密码仅输入一次，鼓励长口令。开启操作前再次验证时，修改主密码前验证旧密码；关闭时允许已解锁会话直接修改。更换使用新盐与新派生参数原子替换，初始密码不作为解锁后门。格式或算法未来升级需要先成功解密验证。
- 离开前台立即锁定，前台无操作默认 5 分钟锁定。清理引用、界面与敏感状态；JavaScript 无法保证物理内存立即擦除，不对此作承诺。返回前台再次解锁。
- 明文不传输到第三方，不加载第三方脚本、字体和分析 SDK；记录内容以文本渲染；网址只允许 http/https；配置 CSP，减少注入风险。加密不能防止已被篡改的网页代码读取解锁后的数据，必须保护 GitHub 账号、审查依赖与发布流程。
- 复制需要主动点击；提示系统剪贴板中已包含敏感内容。不能承诺后台自动清除 iOS 剪贴板，正式版不显示这种保证。
- 生物识别解锁不列入一期，不将普通 WebAuthn 登录错误描述为本地解密能力。

建议目录：

```
src/
  app/                 # 应用入口、布局、路由
  modules/accounts/    # 账号页面、组件、模型与用例
  modules/settings/    # 锁定、备份与恢复
  core/vault/          # 加密封包、锁定状态、密钥生命周期
  core/storage/        # IndexedDB、事务与迁移
  shared/ui/           # 按钮、输入框、弹窗等基础组件
```

解密后的 Account 字段：id、name、username、password（可空）、loginMethod、website、categoryId、notes、isFavorite、createdAt、updatedAt、deletedAt。分类为独立模型；不使用随意扩张的万能字段表。模块共用信息库生命周期与备份协议，各自拥有模型与 schemaVersion。

## 4. 备份、恢复与 iPhone 限制

跨设备迁移是一期核心功能，使用流程固定为：

1. 在电脑浏览器创建信息库并添加账号，数据加密保存在该浏览器的 IndexedDB。
2. 点击“导出数据”，将完整信息库导出为带格式版本的加密文件，包含全部账号字段、分类、收藏与时间信息；后续新增模块统一纳入整库导出。
3. 用户通过“文件”、iCloud Drive、AirDrop 等自行将文件放到手机。系统不负责上传、传输或自动同步。
4. 在手机主屏幕 App 中点击“导入数据”，通过系统文件选择器选择文件，使用该文件的主密码解密。
5. 校验成功后展示文件导出时间、模块及记录数量；确认替换后保存到手机本地，刷新或重开后继续使用。
6. 手机产生新修改后，如要回电脑继续，需重新从手机导出，再在电脑导入。旧导出文件是历史快照，不会随任一设备的修改自动更新。

首次空库导入可直接创建本地库。已有数据时一期采用整库替换，导入不会清空原设备，不会合并两台设备的修改。两边都修改后需要先分别保留导出文件，并自行选定一个版本作为后续使用的主版本。导入预览必须明确提示覆盖当前设备数据，不能默默覆盖。

正式版将数据导入与导出作为“设置与备份”中的同级主要操作；首次空库还提供显著的“导入已有数据”入口。导入成功后显示数量并跳转账号列表，失败或取消保持原库不变。

本地优先不意味着永不丢失。清理网站数据、移除 App、设备丢失、系统存储压力都可能影响数据。正式版申请持久存储并显示结果，但不能将它作为唯一保障。

首次保存账号后引导导出加密备份，并持续显示“上次导出时间”和“尚有未备份更改”。下载备份后用户需要自行放入“文件”、iCloud Drive 或其他可靠位置。页面无法证明下载文件已被妥善保管，因此状态使用“上次导出”，不写“已安全备份”。

备份封包使用带版本的 JSON，包含 salt、KDF 参数、IV、AAD 格式与密文，使用主密码恢复。不同设备导入后需要密码，密钥不随备份以明文保存。导入先限制文件大小与 KDF 参数范围、校验格式及认证标签，在内存中预览数量，再确认替换；替换前要求导出现有库。首期只支持整库替换，不做自动合并。

Safari 和主屏幕 App 的本地存储可能独立。推荐首次使用时先添加到主屏幕，再在主屏幕 App 内创建库；已在 Safari 创建的库使用加密备份迁移。新增同源主屏幕实例也不应假设共享数据库。

## 5. 页面与视觉

方向：浅灰画布、白色卡片、靛紫主色、细边框、轻量留白。品牌 Memo Vault，中文功能文案。品牌不限定账号，容纳未来多个模块。

| 页面 | 桌面 | iPhone |
| --- | --- | --- |
| 空间概览 | 数据摘要、当前模块与后续模块规划 | 单列摘要、进入账号的快捷入口 |
| 账号管理 | 左侧导航 + 账号列表 + 右侧详情 | 底部导航 + 账号列表，点击进入详情 |
| 新增/编辑 | 居中表单弹窗 | 适合软键盘和滚动的表单，至少 16px 输入字号 |
| 解锁 | 正式版有主密码表单，原型提供演示入口 | 独立解锁页，切回前台触发 |
| 设置与备份 | 安全、备份、安装、版本四个区域 | 单列卡片，导入导出优先易达 |

账号列表：搜索名称、登录名、备注；全部/常用/分类切换；最近更新和名称排序。搜索仅在解锁内存数据上运行。详情默认掩码密码，分别提供复制账号、显示密码、复制密码、访问网站、编辑和收藏。第三方登录可以没有密码。

交互：触摸目标正式版至少 44×44 CSS px；关键文字对比度达到 WCAG AA；可见焦点；图标按钮有名称；状态不只用颜色；弹窗约束焦点并支持关闭；适配键盘、动态视口、安全区域和减少动画设置。原型需要进一步做完整可访问性验收。

## 6. PWA 与部署

正式版准备 192/512 PNG 图标、180px apple-touch-icon、maskable 图标、manifest 的 name / short_name / start_url / scope / display: standalone。Vite base、路由、manifest 和 service worker 作用域都使用仓库子路径，例如 /memo-vault/，不硬编码根路径。

Service Worker 只缓存自有应用外壳，不缓存解密记录。账户数据由加密存储层管理，离线也需要解锁。更新提示先等待未保存编辑完成并锁定，再激活新版。历史缓存按版本清理。旧版与新版的数据格式迁移需要回滚策略，不能在用户编辑过程中强制刷新。

GitHub Actions 流程：推送 main → 锁文件安装依赖 → 类型检查与测试 → Vite 构建 → 上传 Pages artifact → 部署 Pages。限制工作流权限、固定 action 的版本/提交，并启用 HTTPS。实际创建仓库和发布在后续部署阶段进行，本次不执行。

## 7. 开发顺序与验收

1. 当前阶段：确认信息架构与响应式页面，提供虚构数据交互原型。
2. 正式工程：Vue/TS/Vite、账号 CRUD、分类、搜索、收藏、回收站；不在加密完成前存真实数据。
3. 安全存储：初始化与解锁、原子保存、锁定、并发控制、备份恢复、迁移测试。
4. PWA 与发布：离线缓存、仓库子路径、Actions、iPhone Safari 和主屏幕真机验收。

核心验收：刷新后仍能解密读取；数据库和备份中不存在平台名、账号、密码等明文；错误密码、篡改备份和中断写入不破坏原库；跨设备导入后数据一致；切后台锁定；断网重开能解锁；旧版本升级不丢数据；iPhone 键盘不遮挡保存按钮。密码管理涉及敏感数据，上线保存真实凭据之前应完成独立安全审查。
